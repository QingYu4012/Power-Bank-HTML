# Power Bank HTML 网页升级操作说明

通过网页的 **更新程序** 界面可以读取设备的升级状态、下载 `.bin` 文件并核对设备写入结果。完整命令帧、Option Bytes 字段、校验算法和 HEX 示例见 [Power Bank HTML 网页通信协议](../Power-Bank-HTML通讯协议.docx)。

## 进入更新程序

1. 用支持 Web Serial 的 Chrome 或 Edge 打开网页，选择设备的串口和波特率并连接。串口使用 8 个数据位、1 个停止位、无校验、无流控。
2. 在数据页连续点击 **充电宝数据监测** 标题 5 次，进入开发者模式。登录管理员后点击 **更新程序**。
3. 网页暂停普通数据轮询，以 `AA 55` 帧发送 `GET_ACK`。收到就绪应答 `01` 后，网页读取 `GET_OPTION_BYTES`。每条 IAP 控制命令发送前均先进行此确认。每次最多等待 300 毫秒，未确认时再发送一次。两次未确认时，本次控制命令不发送。
4. 在 **Option Bytes** 区域确认 `BOOT_State`、`APP_SIZE`、`APP_CRC32` 和 APP 容量。设备同时提供文件协议、文件名和原始大小时，网页会显示对应信息。

## 选择文件和传输协议

点击 **选择文件**，选取非空的 `.bin` 文件。网页显示文件名、原始大小、传输大小和 CRC-32。目录信息取决于浏览器能读取的文件属性。

| 网页选项 | 数据块大小 | 传输大小和 CRC-32 的计算范围 |
| --- | ---: | --- |
| Xmodem - 128 | 128 字节 | 原始文件加末块补齐字节 |
| Xmodem - 1K | 1024 字节 | 原始文件加末块补齐字节 |
| Ymodem - 128 | 128 字节 | 原始文件 |
| Ymodem - 1K（默认） | 1024 字节 | 原始文件 |

数据块不足时用 `0x1A` 补齐。Ymodem 用 0 号文件信息包传递文件名和原始大小。网页按设备发送的请求自动选择包校验，`C`（`0x43`）选择 CRC-16，`NAK`（`0x15`）选择数据区 8 位和校验。

## 下载和结果确认

1. 点击 **下载**。网页重新确认 `GET_ACK`，读取本次的 `GET_OPTION_BYTES`，用设备报告的 APP 容量检查传输大小。容量缺失、小于 8 字节或小于传输大小时，下载在切换引导状态前终止。
2. 网页根据设备状态请求进入 BootLoader 升级状态。设备进入 `BOOT_STATE_APP_UPDATA` 后，网页确认 `GET_ACK` 就绪，再发送 `SET_TRANSFER_INFO`（`0x03`）。其 8 字节载荷由传输大小和 CRC-32 两个小端 32 位字段组成。收到成功响应 `01` 后，网页等待设备发送 `C` 或 `NAK`，最长等待 10 秒。
3. 网页按顺序发送数据块，设备以 `ACK`（`0x06`）确认。原始 XYmodem 数据包、结束字符和重传之间不插入 IAP 唤醒帧。进度和剩余字节按已确认的数据更新。数据块收到 `NAK` 或等待确认超时，网页延时 80 毫秒重发。每次等待确认最多 5 秒，同一阶段第 5 次失败会终止传输。
4. 数据块全部确认后，网页发送 `EOT`（`0x04`）并等待 `ACK`。Ymodem 在 `EOT` 确认后继续等待设备的 `C` 或 `NAK`，发送 0 号结束空包，再等待最后一次 `ACK`。
5. 网页在结束握手后约 800 毫秒重新读取 Option Bytes，最多尝试 5 次，每次都先确认 `GET_ACK`。设备的 `APP_Key` 等于 `0xAA55BBDD`、`BOOT_State` 为 `READY`、`APP_UPDATA_READY`、`JUMP_APP` 或 `APP`，且 `APP_SIZE` 和 `APP_CRC32` 都与本地值相同，页面才报告校验通过。

## 取消和排查

设备发送 `CAN`（`0x18`）时，网页中止当前下载。在操作期间点击 **返回数据界面** 或 **返回开发者模式** 会取消本轮操作。串口仍连接时，网页在已排队的写入之后发送 `18 18`，并排空随后 600 毫秒内收到的旧数据。取消写入失败时，网页会断开串口。

| 页面现象 | 检查项 |
| --- | --- |
| 一直等待 `GET_ACK` | 核对串口、波特率和设备的 IAP 控制帧响应。 |
| APP 容量未提供或镜像超过容量 | 查看 Option Bytes 中的 APP 容量，并按所选协议核对传输大小。 |
| 限时内未收到 `C` 或 `NAK` | 在 IAP 日志中核对引导状态和升级清单响应。 |
| 收到 `NAK`、`CAN` 或发生超时 | 查找日志中对应的文件信息包、数据块、`EOT` 或结束空包阶段。 |
| 进度达 100% 后校验失败 | 对照日志中的设备状态、`APP_Key`、大小和 CRC-32，确认是否读到本轮写入结果。 |
